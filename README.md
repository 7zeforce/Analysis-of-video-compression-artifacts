# Анализ артефактов сжатия видео

Веб-приложение, которое сжимает видео до 2 Мбит/с, покадрово сравнивает результат с оригиналом дифференциальным методом и показывает, где именно кодек потерял качество.

## 1. Описание программы

### Что она делает

1. **Сжимает видео** кодеком H.264 с битрейтом 2 Мбит/с, сохраняя исходное разрешение и соотношение сторон. Масштабирование не применяется, параметры SAR и DAR переносятся из исходного файла без изменений.
2. **Оценивает качество дифференциальным методом.** Каждый кадр оригинала и сжатой копии переводится в цветовое пространство YCrCb и разделяется на компоненты. Для каждой компоненты каждого кадра считаются:

   | Метрика | Формула | Смысл |
   | --- | --- | --- |
   | MAE | среднее модуля разности | средняя ошибка на пиксель |
   | MSE | среднее квадрата разности | сильнее штрафует крупные выбросы |
   | PSNR | `10·log₁₀(255² / MSE)` | отношение сигнал/шум в дБ, выше — лучше |
   | DiffMax | максимум модуля разности | худший пиксель кадра |

3. **Строит видео с визуализацией артефактов** — разность кадров с усилением контраста, в трёх режимах.
4. **Строит график «кадр → средняя ошибка»** по всей длине ролика.
5. **Находит кадр с максимальной ошибкой**, выводит его таймкод и отмечает на графике вертикальным пунктиром с подписью. Кнопка «Перейти к кадру» перематывает оба плеера на это место.
6. **Отдаёт результаты на скачивание** — видео с артефактами и изображение графика.

### Настраиваемые параметры

| Что настраивается | Варианты |
| --- | --- |
| Режим визуализации артефактов | чёрный фон с модулем разности, серый фон со знаком разности, тепловая карта (палитра turbo) |
| Усиление контраста артефактов | от 1× до 64×, с автоподбором по формуле `255 / DiffMax` |
| Критерий графика | MAE, MSE, PSNR, максимальная разность |
| Масштаб оси Y | авто по данным, от нуля, логарифмический |
| Ось X | время или номера кадров |
| Диапазон кадров | произвольный отрезок «с … по …» |
| Формат сохранения графика | PNG или JPEG, с увеличением 1×, 2× или 3× |

Предпросмотр и видео с артефактами, и графика доступен прямо на странице до сохранения файла.

### Возможности и ограничения

**Возможности**

- Пример видео заложен в образ и появляется на сайте сразу после запуска — загружать что-либо вручную не требуется.
- Собственное видео загружается кнопкой или перетаскиванием. Поддерживаются mp4, webm, ogg, mov, mkv, avi, wmv, flv, m4v; всё, кроме mp4 и webm, конвертируется в mp4 на сервере.
- Оригинал и сжатая копия проигрываются рядом, с синхронным воспроизведением.
- Долгие операции выполняются в фоне, страница показывает прогресс по кадрам.

**Ограничения**

- **Одно видео за раз.** Загрузка нового файла удаляет предыдущее вместе со сжатыми копиями.
- **Результаты анализа живут в оперативной памяти.** После перезапуска контейнера или перезагрузки страницы анализ нужно запустить заново; в базе хранятся только сами видеофайлы.
- **Кадры сравниваются последовательно**, первый с первым. Если частота кадров оригинала и копии различается, приложение выводит предупреждение, но сравнение не прерывает — в этом случае метрики недостоверны.
- **График строится по компоненте Y.** Значения по Cr и Cb доступны в сводной таблице, но на график не выводятся.
- Для отображения график прореживается до 2000 точек. Кадр с максимальной ошибкой при этом ищется по полным данным, без прореживания.

## 2. Системные требования

### Запуск Docker Image (основной способ)

- Docker Engine 20.10 или новее, архитектура **linux/amd64**.
- Около 1.3 ГБ места под образ плюс место под обрабатываемые видео.
- 2 ГБ оперативной памяти. Метрики всех кадров держатся в памяти до конца анализа, поэтому для длинных роликов требуется больше.
- Свободный порт 8080 на хосте.
- Современный браузер: Chrome, Edge, Firefox или Safari актуальных версий. Интерфейс использует `canvas`, `fetch` и синтаксис ES2020.

Отдельно устанавливать .NET, ffmpeg или OpenCV не нужно — всё внутри образа.

### Запуск из исходного кода

- .NET SDK 10.0.
- ffmpeg, доступный в `PATH` (нужны кодировщики libx264 и aac, а также фильтры `blend` и `pseudocolor`).
- Windows x64 или Linux x64. На Linux дополнительно нужны системные библиотеки `libgtk-3-0` и `libatomic1` — от них зависит нативная часть OpenCvSharp.

## 3. Запуск и загрузка данных

### Из Docker Image

```bash
docker pull registry.miem.hse.ru/kg26-27/midmsmirnov:latest
```

```bash
docker run -d -p 8080:8080 --name video-artifacts registry.miem.hse.ru/kg26-27/midmsmirnov:latest
```

Открыть **http://localhost:8080**. HTTPS в контейнере не настроен, поэтому адрес именно `http://`.

Остановить и удалить контейнер:

```bash
docker rm -f video-artifacts
```

Томов и переменных окружения для запуска не требуется: образ слушает порт 8080, создаёт базу SQLite при старте и сам кладёт пример видео на сайт.

### Через docker compose

Из папки `AnalysisApplication`:

```bash
docker compose up -d --build
```

Compose дополнительно монтирует `./uploads` в `/app/wwwroot/videos` и `./data` в `/app/Data`, поэтому загруженные видео и база переживают пересоздание контейнера.

### Из исходного кода

Из папки `AnalysisApplication`:

```bash
dotnet run
```

Поднимется профиль `http` на http://localhost:5130. Вариант с HTTPS — `dotnet run --launch-profile https`, он слушает https://localhost:7227 и http://localhost:5130. База SQLite создаётся автоматически рядом с собранным приложением (`Data/app.db`), миграции применяются при старте.

### Загрузка данных

**Видео по умолчанию.** При первом запуске приложение берёт файл, указанный в `appsettings.json` ключом `DefaultVideo` (по умолчанию `Samples/stolica_dv.mp4`), копирует его в рабочую папку и регистрирует в базе. Файл уже лежит в образе, поэтому видео доступно на сайте сразу. Если в базе уже есть видео, подстановка не выполняется и ранее загруженный файл сохраняется.

**Своё видео** загружается кнопкой «Заменить видео» или перетаскиванием файла на карточку. Ограничение на размер — 2 ГБ. Файлы сохраняются в `wwwroot/videos` под именами-идентификаторами, исходные имена хранятся в базе.

**Порядок работы**

1. Нажать «Сжать и оценить». Приложение сожмёт видео до 2 Мбит/с и покадрово сравнит копию с оригиналом, показывая прогресс.
2. В карточке результатов появятся сводные метрики по Y, Cr, Cb, кадр с максимальной ошибкой и его таймкод.
3. В карточке графика выбрать критерий, масштаб осей и диапазон кадров, затем нажать «Скачать график».
4. В карточке «Видео с артефактами» выбрать режим и усиление, нажать «Построить видео», посмотреть результат на странице и скачать.

### Режимы визуализации артефактов

| Режим | Что показывает |
| --- | --- |
| чёрный фон, модуль разности | артефакты светятся на чёрном, самый наглядный вариант |
| серый фон, со знаком разности | светлее середины — кодек завысил яркость, темнее — занизил |
| тепловая карта | палитра turbo: синий — разницы нет, голубой и зелёный — сильная ошибка |

Усиление необходимо потому, что в чистом виде разность почти не видна: на тестовом ролике средний модуль разности по яркости составляет около 1.7 из 255.

## API

Все ответы в JSON, поле `ok` сообщает об успехе. Долгие операции возвращают `jobId`, по которому опрашивается статус.

| Метод и маршрут | Назначение |
| --- | --- |
| `POST /Video/Upload` | загрузка файла (multipart, поле `file`) |
| `GET /Video/List` | список видео |
| `POST /Video/Delete?id=` | удаление видео вместе со сжатыми копиями |
| `POST /Video/Compress?id=&bitrate=2000` | сжатие до указанного битрейта |
| `POST /Estimation/Start?id=` | запуск анализа сжатой копии |
| `GET /Estimation/Status?jobId=&points=2000` | прогресс и результаты анализа |
| `POST /Artifacts/Start?id=&gain=&mode=` | сборка видео с артефактами (`gray`, `signed`, `heat`) |
| `GET /Artifacts/Status?jobId=` | прогресс сборки и ссылка на готовый файл |
